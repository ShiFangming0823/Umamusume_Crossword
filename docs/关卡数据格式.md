# 关卡与名字词典管理

> v0.7 起，这份文档保存历史固定棋盘与来源资料；当前游戏使用随机提示库，见 [随机题库与生成算法](随机题库与生成算法.md)。

网页现在直接读取 JSON 数据。关卡不再写死在网页脚本中，添加同类关卡不需要修改交互代码。

## 文件职责

| 文件 | 内容 |
| --- | --- |
| `data/levels/index.json` | 关卡清单、顺序、启用状态 |
| `data/levels/beginner-1-en.json` | 入门版 1，英文答案，中文/英文/日文提示 |
| `data/levels/beginner-1-kana.json` | 入门版 1，片假名答案；原19×20入门盘面 |
| `data/levels/advanced-1-en.json` | 进阶版 1，英文答案，中文/英文/日文提示 |
| `data/levels/advanced-1-kana.json` | 进阶版 1，片假名答案，中文/英文/日文提示 |
| `data/levels/epithets-1-en.json` | 专属称号 1，英文答案，中文/英文/日文提示 |
| `data/levels/epithets-1-kana.json` | 专属称号 1，片假名答案，中文/英文/日文提示 |
| `data/levels/cinderella-1-en.json` | 芦毛灰姑娘 1，英文答案，中文/英文/日文提示 |
| `data/levels/cinderella-1-kana.json` | 芦毛灰姑娘 1，片假名答案，中文/英文/日文提示 |
| `data/cinderella-gray.json` | 芦毛灰姑娘逐题剧情范围、三语提示与来源 |
| `data/epithets.json` | 指定来源的145行二つ名对照及入题三语提示；保留缺失项 |
| `data/characters.json` | 独立角色名字词典，目前 97 位；包括八套题的全部角色 |
| `src/i18n.js` | 按钮、菜单、弹窗等界面文案 |
| `schemas/` | 编辑器可用的 JSON Schema |

四个题组都同时提供英文和片假名关卡。入门片假名已归回入门题组；进阶片假名与进阶英文题采用同样22位角色和三语提示，独立排盘。两种填答语言的编号和方向可能不同，应通过 `characterId` 对照角色。题组分类与游玩模式相互独立。

## 关卡结构（schemaVersion: 1）

下面是字段示意；盘面和 entries 必须一起组成完整、互相交叉的字谜，不能把示例片段直接当作新关卡发布。

```json
{
  "schemaVersion": 1,
  "id": "beginner-2-en",
  "title": { "zh-CN": "入门版 2 · 英文", "en": "Starter 2 · English", "ja": "入門 2・英字" },
  "description": { "zh-CN": "题目介绍", "en": "Puzzle description", "ja": "問題の紹介" },
  "difficulty": "beginner",
  "answerLanguage": "en",
  "grid": { "rows": 24, "columns": 24, "layout": ["...请参考实际关卡文件..."] },
  "entries": [
    {
      "id": "5-across",
      "number": 5,
      "direction": "across",
      "row": 2,
      "column": 9,
      "characterId": "meisho-doto",
      "answer": "MEISHODOTO",
      "clues": { "zh-CN": "中文提示", "en": "English clue", "ja": "日本語のヒント" }
    }
  ]
}
```

- `id`：唯一、稳定的关卡标识，仅用小写英文字母、数字与连字符。
- `title`、`description`、`clues`：都必须提供 `zh-CN`、`en`、`ja` 三份文案。切换界面语言时按这些键读取。
- `difficulty`：历史字段名，现表示题目类别。`beginner` 是入门题组，`advanced` 是进阶题组，`epithets` 是专属称号，`cinderella` 是赛马娘 芦毛灰姑娘。它与辅助/挑战游玩模式独立。
- `answerLanguage`：`en` 是英文，`ja` 是片假名；与界面语言无关。
- `grid.layout`：每个字符串是一行，`#` 表示不可填格，`.` 表示白格。字符串数等于 `rows`，每行长度等于 `columns`。
- `row`、`column`：答案起点，**从 0 开始**。例中 `2,9` 表示人类习惯的第 3 行、第 10 列。
- `direction`：`across` 向右，`down` 向下。
- `number`：题面显示的数字，按起点从上到下、从左到右依次编号；同一个起点的横纵答案共享编号。
- `characterId`：对应名字词典中的角色 ID。正确后的名字展示由该字段关联。
- `answer`：真正填入格子的完整字符串。英文大写且去除空格、标点；片假名保留小写假名和长音「ー」。每个字符一格，「ガ」「パ」是带浊点/半浊点的单一字符，各占一格。

答案显式保存在每条 entry 中，方便编辑与检查。黑白格布局不重复保存答案文字。英文答案还会与角色英文名去除空格/标点后的结果核对，片假名则与角色日文名核对，避免名字词典与题目不一致。

## 新增关卡

1. 复制一份相同填答语言的现有关卡，另存为新文件，例如 `beginner-2-en.json`。
2. 修改唯一 ID、三语标题和介绍、题组、填答语言。
3. 填写新盘面和全部答案起点、方向、角色关联及三语提示。长度由答案自动计算，不需要重复维护。
4. 如果使用词典没有的角色，先在 `data/characters.json` 加上对应角色。
5. 在 `data/levels/index.json` 追加：

```json
{ "id": "beginner-2-en", "file": "beginner-2-en.json", "enabled": true }
```

6. 运行 `npm.cmd run check:data`。校验通过后刷新网页，选择菜单中会出现新题。
7. 运行 `npm.cmd test` 和 `npm.cmd run build`，确认发布版本正常。

目录顺序决定选题顺序。临时下架某关卡，将 `enabled` 改为 `false`；文件仍保留，管理校验仍会检查它。

当前页面有入门、进阶、专属称号、赛马娘 芦毛灰姑娘四个题组，每个题组/填答语言下可放多套题。首次选择不存在的组合时，会切换到已有的题组或填答语言，并明确提示原因，不会显示空白棋盘。新增这四类以外的题组时，还需同步扩展分类菜单、`src/game.js` 的类别检查、三语分类文案和关卡 Schema。

专属称号提示仍使用普通三语 `clues` 字段；游戏和毛巾二つ名用 `\n` 分行。不要把原表空白的毛巾栏自动补成游戏二つ名。二つ名原文、来源与缺失状态保存在 `data/epithets.json`；出题时将三语提示同步保存到对应记录的 `clues` 和关卡文件。构建会检查日文提示是否完整保留两项、三语提示是否与来源记录一致。详见 `docs/二つ名来源与映射.md`。

芦毛灰姑娘题组的角色范围和逐题来源保存在 `data/cinderella-gray.json`，包括 `characterId`、三语名字、三语提示、剧情范围 `scene` 和来源链接 `sources`。提示在此文件与两种填答版本中保持同步，构建会检查。作品原创角色同样加入通用名字词典，填答规则与其他关卡相同。查询别名只影响搜索，标准答案仍是关卡文件的 `answer`。

## 新增角色与搜索别名

```json
{
  "id": "oguri-cap",
  "names": { "zh-CN": "小栗帽", "en": "Oguri Cap", "ja": "オグリキャップ" },
  "aliases": ["其他常用译名或昵称"],
  "source": "https://umamusume.jp/character/oguricap"
}
```

三种名字始终一并展示。搜索支持名字片段、不区分英文字母大小写，忽略空格和标点；半角假名会转换为全角，平假名可匹配片假名。繁体译名、昵称、其他拼写请放入 `aliases`。目前只对已维护的别名做匹配，不会自动推断所有繁简转换、罗马字或中文读音。

词典独立于当前关卡，因此可搜索当前题里没有的角色。它是人工维护的本地词典，并非完整的实时官方角色数据库。

## 校验与发布

程序在网页加载和打包时都会检查：三语文案、角色关联、答案写法、盘面尺寸、答案是否越界、交叉字是否一致、是否存在额外的连续字串、编号顺序、白格是否遗漏、所有答案是否连通。

VS Code 可通过 `.vscode/settings.json` 对 JSON 给出字段提示。Schema 负责字段类型；交叉逻辑由 `src/game.js` 的 `validateLevel` 负责。

新关卡和词典会随 `data/` 一起打包至 `dist/`。GitHub Pages 仍直接托管静态文件，无需额外后端或数据库。
