# 随机题统计服务：部署与维护（v0.7）

当前统计按题组和大小棋盘汇总，英字与片假名合并。统计局数，不统计去重玩家。开始局、成功局、平均成功用时是唯一展示指标；提前结束不算成功，模式与答案帮助不再另设统计分组。

v0.7.2扩充至198位角色后，数据库结构和已有统计保持不变，但必须先发布重新生成的 `worker/pool.generated.js` 所属Worker，再发布前端。已完成v0.7升级的环境无需新增D1迁移；旧候选池会拒绝新角色的开始统计。更换名单本身不清空八类汇总数据。

## 模块与数据

- /api/v2/runs/start：接收 runId、difficulty、boardSize、board。board 仅含文字类型、盘面和角色位置。服务端通过 pool.generated.js 重建标准答案，验证角色集合、横纵题数、连通性、交叉和白格覆盖，只保存解答 SHA-256 摘要。
- /api/v2/runs/finish：同一 runId、题组、尺寸，另带 outcome（solved/revealed）和 elapsedMs；成功时带 values 核对哈希。原子状态转移与触发器保证重试不重复累计。
- /api/v2/stats?difficulty=beginner&boardSize=small：只返回 difficulty、boardSize、starts、solved、averageMs。无成功时 averageMs 为 null。
- /api/v2/health：验证新表可读，返回 ok=true、version=2。
- random_game_runs 保存去重 ID、范围、解答摘要、起止时间、状态和用时；category_stats 主键为题组和尺寸，保存计数及成功用时总和。

同域 Pages Function 的 STATS 绑定、Worker 的 DB 绑定与生产来源检查保持不变。旧 /api/runs/*、/api/stats 及旧表由 legacy-worker.js 兼容。旧固定棋盘无小盘，题数和口径也不同，不回填新统计。

不保存 IP、查询词、明文解答或长期访客 ID。浏览器的待上报队列可能临时保存盘面和完成字母，最长7天，成功或永久失败后清理；这不等于存入 D1。公开接口不提供单局明细。统计适合使用情况参考，不是防作弊或有奖排名系统；公开题库与客户端计时不能证明真实玩家操作。

## 从 v0.6 升级

本次代码提交不会自动执行远程迁移或发布 Worker。上线顺序必须为数据库 → Worker → 前端。

1. 在根目录执行 npm run check:data、npm run build:worker、npm test、npm run build。
2. 确认 worker/wrangler.jsonc 中账户对应的 D1 ID 与 DB 绑定正确。
3. 在 worker/ 目录执行下列命令（Windows 可用 npx.cmd）：


    npx --yes wrangler@4.151.0 d1 migrations apply umamusume-crossword-stats --remote
    npx --yes wrangler@4.151.0 deploy

4. 最后推送前端，触发已配置的 Pages 构建。只发前端会使新统计暂时不可用，但不会阻止游玩。
5. 检查 /api/v2/health，并对八个题组／尺寸范围确认开始、成功、提前结束和平均用时。不要用正式玩家数据做自动化测试。

0002_random_stats.sql 只创建新表、索引和触发器；不删除、覆盖旧统计，重复初始化不会清空新数据。Wrangler 迁移工具会管理已应用记录。旧客户端可在切换期间继续访问旧接口。

## 本地验证

Node 测试用真实内存 SQLite 执行两种统计的 SQL 与重试流程。Worker 打包检查可在 worker/ 运行 npx --yes wrangler@4.151.0 deploy --dry-run --outdir ../.worker-build，不会发布服务。

需要联调 D1 时，在 worker/ 执行 migrations apply 的 --local 形式，并用 wrangler dev --var ALLOWED_ORIGINS:http://localhost:5173 启动隔离库。临时将 src/analytics-config.js 的 apiBaseUrl 指向本地 Worker，结束后恢复；不要把本地端口写入正式提交。普通 npm run dev 不运行 Pages Function，默认不写生产统计。

服务端标准名字或题组候选发生变化时重新运行 build:worker，提交 pool.generated.js，先发 Worker 后发前端。删除原有候选会让还未上报的旧局无法通过校验，应考虑兼容窗口；不要随意批量改已有角色 ID。

查询汇总示例：

    SELECT category, board_size, starts, solved,
      CASE WHEN solved > 0 THEN ROUND(elapsed_total_ms * 1.0 / solved / 1000, 1) END AS average_seconds
    FROM category_stats ORDER BY category, board_size;

## v0.6 历史维护资料

以下是旧固定题协议资料，仅用于兼容与历史查询。新功能以上面的 v2 说明为准。


静态前端通过同域 `/api/` 上报。Pages Function 使用 `STATS` 服务绑定调用独立 Cloudflare Worker，Worker 使用 `DB` 访问 D1；浏览器不直接请求 `workers.dev`。前端不存放 Cloudflare API Token。

## 统计口径

| 指标 | 定义 |
| --- | --- |
| 开始局数 | 创建新会话时计一次；重新开始和应用不同关卡计新局 |
| 成功通关 | 服务端确认整张盘面正确后计一次，相同 `runId` 不重复累计 |
| 平均通关用时 | 成功局的毫秒总和除以成功局数，包含辅助通关；无人完成时为 `null` |
| 全程挑战 | 从未使用过辅助模式、没有查看答案的成功局，单列数量和平均用时 |
| 提前结束 | 保存为 `revealed`，不计通关和平均用时 |

界面语言、游玩模式切换和取消设置不增加开始局数。任何时候使用辅助模式，本局都不再计入全程挑战。有效的非空名字查询（包括未命中）会计数，不上传查询词；同一答案重复查看不增加查看次数。

从 v0.6.1 起，辅助模式无限次查看答案，挑战模式每局可揭示3道题并自动填入、标绿、锁定，两种模式都能提前结束。`everAssisted` 表示曾进入辅助模式或查看过任意答案，`revealCount` 是两种模式合计查看过的不同题目数，最大值为该关卡的题目数；挑战模式配额另由会话的 `hardRevealedEntries` 管理。使用挑战揭示后正常填完仍计总通关，但不会混入无答案帮助的全程挑战成绩。

统计的是局数，不是独立人数。每局随机 UUID 仅用于去重，不使用账号、设备指纹或长期访客标识。数据库不保存姓名、IP、查询词或答案；成功时只在请求处理过程中核对盘面。Cloudflare 平台本身的数据处理遵循其政策。

## 模块与接口

- `src/analytics-config.js`：公开 API 地址及生产来源。
- `src/analytics.js`：上报、超时、待上报队列和统计缓存。
- `src/analytics-protocol.js`：题目内容版本及标准盘面。
- `worker/index.js`：接口、来源检查、大小限制、输入和答案校验。
- `worker/levels.generated.js`：生成的版本和标准盘面，需提交到仓库。
- `worker/wrangler.jsonc`：Worker 名称、D1 绑定与允许来源。
- `worker/migrations/0001_stats.sql`：两张表、索引及汇总触发器；重复执行不删除已有数据。
- `functions/api/[[path]].js`：同域转发入口，绑定不可用时返回503。
- 根目录 `wrangler.jsonc`：Pages 的 `STATS` 服务绑定；预览部署的服务列表为空，避免写生产库。
- `_routes.json`：只对 `/api/*` 执行 Function，其他页面和静态资源继续使用静态托管。
- `tests/statistics.test.js`：用 Node.js 内置 SQLite 测试真实 SQL 和上报流程。

| 接口 | 用途 |
| --- | --- |
| `GET /api/health` | 检查数据库连接 |
| `POST /api/runs/start` | 开始一局，相同 ID 重试不重复计数 |
| `POST /api/runs/finish` | 成功或提前结束，已结束的局不能再次累计 |
| `GET /api/stats?levelId=…&revision=…` | 只返回一个关卡版本的汇总 |

开始请求包含 `runId`、`levelId`、`revision`、`startMode`；结束请求增加 `outcome`、`elapsedMs`、`finishedMode`、`everAssisted`、`lookupCount`、`revealCount`。只有成功请求需携带 `values` 供校验。JSON 大小上限32 KiB，用时上限7天。

## 部署

数据库名称为 `umamusume-crossword-stats`。确认 `worker/wrangler.jsonc` 中的 `database_id` 属于当前账户，绑定名为 `DB`。数据库 ID 不是访问凭据。

从项目根目录运行：

```sh
npm run build:worker
npm test
```

然后在 `worker/` 目录运行：

```sh
npx --yes wrangler@4.151.0 login
npx --yes wrangler@4.151.0 d1 migrations apply umamusume-crossword-stats --remote
npx --yes wrangler@4.151.0 deploy
```

v0.6.1 无需数据库迁移。更新现有部署时，先发布本次 Worker（支持无限查看与辅助模式提前结束的统计请求），再发布前端；只推送前端会使旧 Worker 拒绝这些新规则的结束请求。新 Worker 兼容旧版前端。

Windows PowerShell 可用 `npx.cmd` 代替 `npx`。Wrangler 与控制台使用各自的登录；希望存入系统凭据库时先安装 `@napi-rs/keyring@1.3.0`，登录增加 `--use-keyring`。不要提交凭据文件。若已通过 D1 控制台初始化 SQL，再执行迁移也不会清空数据。

前端 `src/analytics-config.js` 的 `apiBaseUrl` 和 `productionOrigin` 均为 `https://umamusume-crossword.pages.dev`，不包含 `/api` 或末尾斜杠。Worker 的 `ALLOWED_ORIGINS` 使用同一来源。

根目录 `wrangler.jsonc` 为现有 Pages 项目配置 `STATS → umamusume-crossword-stats`，并指定 `dist` 产物目录。提交 `functions/`、根目录配置和更新的前端代码后，Pages 的 Git 构建会编译 Function 并应用绑定。不需要将 `functions/` 复制为静态文件，也不要在根目录运行普通 `wrangler deploy`；Worker 发布命令应在 `worker/` 内执行。

默认本地预览和其他预览域名不发送生产统计。前端发布后检查 `https://umamusume-crossword.pages.dev/api/health`，正常返回 `{"ok":true,"version":1}`；然后测试开始、重新开始、成功及提前结束。语言和模式切换不能增加开始局数。

## 维护与限制

`game_runs` 保存单局状态；数据库触发器维护 `level_stats` 汇总。读取汇总通过主键定位，不扫描全部明细。请求只允许已知关卡和内容版本，并校验完成盘面。公开读接口不返回单局明细，数据库管理权限不暴露给浏览器。

关卡的盘面、答案、编号和三语线索参与 SHA-256 版本计算。修改题库后运行 `npm run build:worker`，先发布 Worker，再发布前端；旧数据仍保留，不混入新版统计。旧版待上报记录若已不受支持，将被拒绝并从队列移除。

本机待上报记录使用 `localStorage` 的 `tracen-stats-pending-v1:` 前缀，不恢复游戏盘面。联网、重新打开网页、返回页面时补报；失败退避重试。记录7天后过期，每次恢复最多读取50条。清除浏览器数据或关闭页面后不再访问，可能漏报。网络或统计故障不阻塞游戏。

在 D1 控制台可查询：

```sql
SELECT level_id, revision, starts, solved,
  CASE WHEN solved > 0 THEN ROUND(elapsed_total_ms * 1.0 / solved / 1000, 1) END AS average_seconds,
  challenge_solved
FROM level_stats ORDER BY level_id;
```

统计适合了解使用情况，不适合有奖排名：用时和帮助历史由客户端上报，题库公开也使答案校验无法防作弊。CORS 是正常网页的来源限制，不是身份验证或防刷；出现滥用时可再增加频率限制或 Turnstile。不要直接删除用于去重的明细后又允许旧 ID 重新累计。

官方资料：[D1 创建与绑定](https://developers.cloudflare.com/d1/get-started/)、[D1 定价](https://developers.cloudflare.com/d1/platform/pricing/)、[Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)。服务单独消耗 Workers 和 D1 额度，以控制台为准，本实现不要求预先升级付费计划。
