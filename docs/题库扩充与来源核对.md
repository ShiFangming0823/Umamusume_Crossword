## 核对方法

- **官方人物资料**：[Cygames角色目录](https://umamusume.jp/character)。读取公开页面内的JSON数据，逐位核对名字、设定及配音；不执行网页脚本。单条提示中的关系若来自另一位角色介绍，同时参考对应角色资料。动画、电影、游戏剧本使用相应官方介绍作补充。
- **比赛结果**：[JRA历年GⅠ结果](https://www.jra.go.jp/datafile/seiseki/replay/g1.html)。核对305场冠军结果与25条重要入着记录；每条冠军提示指向具体年份的正式结果页，不只挂一个赛事主页。额外重赏及海外成绩参考[JBIS](https://www.jbis.or.jp/)和主办机构资料。保留历史名称、距离和级别，例如2001年迪拜司马经典赛当时为GⅡ，旧高松宫杯为2000米。
- **血统**：仅使用JRA具体结果页「勝馬の情報」实际列出的父母，且只把词典里已有的父母名字用于这类提示。明确写成「原型马」亲子关系，不能移植为作品中的母女设定。
- **音乐**：[Lantis官方唱片目录](https://umamusume.lantis.jp/discography/)。按具体唱片曲目和歌唱署名核对，排除多人合唱、不同演唱版本混淆和配音剧；曲名保留原题，不凭空译出一首新歌。仅纳入核对日之前已发行的录音。
- **官方企划**：使用官方视频链接、可核对的发布日期和完整参与名单。节目为 **ぱかチューブっ!** 的游戏实况企划，不能笼统称为「ぱかライブ」直播。多人企划需补上角色特征或视频视角，不能仅凭参与该企划来对应一个答案。本次未把未直接核实的游戏内输赢、职业选择或击杀细节写进提示。
- **近况**：优先参考照料机构、牧场和现场记录；提示正文包含资料月份或年份，并保存 `asOf`。资料时间代表当时事实，不承诺牧场位置或接待安排永久不变。

机器可检查格式、重复文字、事实键、来源和日期，却不能证明事实本身为真，也不能证明语义完全唯一。投稿仍需人工审校。近况或长时间未更新的资料应优先复核，不能把网页可访问当成事实已核实。

## 近况与企划的具体来源

- 名将怒涛：[引退马协会2026-09-28报告](https://rha.or.jp/f/doto-shuttle/20260928-001.html)，明确报告它在北湖牧场的生活及30岁年龄。
- 高尚骏逸、防暴装束：[北国马匹公园厩舍页](https://www.northern-horsepark.jp/horse/stable/)，核对日在厩舍3名单中；分别附2017年日本杯、2018年有马纪念以保持唯一性。
- 奇锐骏：[凡尔赛牧场交流活动页](https://www.versailles-resort.com/service-page/ワンダーアキュート-greeting-定員)、[2026年相马野马追现场记录](https://www.loveuma.jp/post/uma-260908)。后一篇为受牧场委托记录者的现场报道，不是根据同人讨论推断参战。
- 2025-12-22《人生游戏》：[官方视频](https://www.youtube.com/watch?v=OqDLJggkXT4)、[标题与概要索引](https://www.tubetre.com/videos/view/OqDLJggkXT4)。四位为小栗帽、玉藻十字、超级小溪、稻荷一。
- 2026-03-01《Among Us 3D》：[官方杏目视角](https://www.youtube.com/watch?v=evayysKQ-mY)、[标题与概要索引](https://www.tubetre.com/videos/view/evayysKQ-mY)、[官方防暴装束视角](https://www.youtube.com/watch?v=f4tG_tfHCe4)。六位为杏目、旺紫丁、防暴装束、机伶金花、唯独爱你、洛林军歌。YouTube在核对环境中不能直接播放，因此本次只使用可交叉核对的企划名单、标题和视角；不声称已观看并核实每段游戏行为。

部分NAR旧页在检索索引里仍有内容，直接请求却返回404；本库相应新提示改用仍可核对的JBIS成绩页或牧场原始报道。个别机构PDF可能限制直接访问，遇到此情形使用同机构的可读报告补证，而不是保留一个失效链接作唯一来源。

结构化赛绩和音乐核对清单位于 [race-results.json](evidence/race-results.json) 与 [music-credits.json](evidence/music-credits.json)。它们便于定位原始资料，游戏运行时仍以 `data/clues.json` 为准。

## 后续维护

1. 手动执行 `npm run audit:roster`，检查官方名单相对上次快照是否有新增、删除、改名、分类或配音变更。此命令访问网络，但只读、不会自动收录新角色。
2. 新角色先补三语名字与至少两条可独立定位的提示，再更新经过人工复核的名单快照。不要把未知工作人员自动加入普通题组。
3. 新提示补 `factKey`、`verifiedAt`、三语正文和可追溯的 `sources`；近况另填 `asOf`，并在正文保留日期。
4. 同一角色相同事实使用同一事实键；不同ID不能用来规避重复事实检查。`factKey`只能辅助检查，语义近似仍需人工处理。
5. 执行 `check:data`、`build:worker`、`test`、`benchmark`、`build`，提交生成的Worker候选池。普通题的全名单覆盖会在离线校验和测试中检查，防止新增词典条目后仍抽不到它。

v0.7.1不改变统计表结构。如果生产环境已升级到v0.7，先发布含新候选池的统计Worker，再发布前端即可；不需要新的D1迁移。若仍是v0.6，则先按v0.7指南完成0002迁移。只更新前端会导致旧Worker拒绝包含新角色的统计，虽然游戏本身仍可运行。
