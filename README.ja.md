# トレセンクロスワード部

[简体中文](README.md) · [English](README.en.md) · **日本語**

ウマ娘の名前を解答とするランダム生成のブラウザクロスワードです。フロントエンドはHTML・CSS・JavaScript ES Modules、名前とヒントはJSONで管理します。任意の匿名統計サービスは、同一オリジンAPIを経由するCloudflare WorkerとD1で構成します。

## 機能

- 入門・発展・二つ名・シンデレラグレイの4問題集。毎回ウマ娘を抽選して交差盤面を生成し、各ヒントも選びます。固定の子問題の選択はありません。
- 画面とヒントは簡体字中国語・英語・日本語。解答の英字／カタカナは独立して設定できます。
- 大盤面はヨコ10問・タテ10問、小盤面は各6問。PCでは大、スマホでは小を初期選択し、手動でも変更可能。横スクロールとマスの拡大縮小に対応します。
- アシストは正解した単語を緑色と3言語の名前で表示し、検索・解答表示は無制限。チャレンジは未表示の解答の正誤を隠し、検索3回・異なる3問の解答表示が可能。表示した単語は自動入力・緑色表示・固定されます。
- 両モードで途中終了して全解答を表示できます。設定や単問のヘルプでは計測を止めません。画面言語・モードの変更は状態を保持し、問題集・文字・サイズの変更適用や新規生成でリセットします。
- PNGを端末内で生成。空白、現在の入力、終了後の解答付き盤面を保存でき、現在の言語のヒント・ゲームURL・オフラインQRコードを収録します。時間と状態は任意です。
- プレイ画面と終了画面にGitHub Issue・メールでのヒント投稿窓口があります。
- 統計は問題集×サイズの8区分。開始数・クリア数・平均クリア時間のみを表示し、英字とカタカナは合算します。人数ではなくゲーム数です。

## 開発環境

Node.js 24を使用します。npm依存のインストールは不要です。QRエンコーダーはMITライセンスを保持して同梱しています。ES Modules、Fetch、Web Worker、Canvas、ネイティブdialog対応ブラウザでHTTP経由で開いてください。

| コマンド | 用途 |
| --- | --- |
| npm run dev | ソースを http://localhost:5173/ でプレビュー |
| npm run check:data | 名簿全体の収録・名前・ヒント・旧問題をオフライン検証 |
| npm run audit:roster | 公式名簿の追加・改名・分類・配役変更をオンライン照合。自動追加はしない |
| npm test | ルール、生成盤面、翻訳、API、実SQLiteの回帰テスト |
| npm run benchmark | 問題集・文字・サイズの全16組を測定 |
| npm run build:worker | サーバー候補プールと旧版互換データを生成。生成物もコミット |
| npm run build | データ検証後にdist/を再作成。テストは別途実行 |
| npm run preview | ビルド済みdist/をプレビュー |

PowerShellではnpm.cmdも使用可能です。両プレビューの既定ポートは5173で、同時実行時はPORTを変更します。

## 構成

main.jsはDOM・入力法・貼り付け・フォーカス・設定・セッションを編成し、game.jsのGameSessionがDOM非依存の計時・判定・モード・回数制限・正規化・検索・盤面検証を担当します。catalog.jsとclue-bank.jsがデータを読み込み検証します。generator.jsが有界のランダム再試行探索を行い、generator-worker.jsが別スレッドで実行します。i18n.jsとrandom-i18n.jsは画面翻訳、export.jsとvendor/は画像出力です。

生成では重複なしにウマ娘を選び、交差文字、単語の前後、側面の隣接、連結性、ヨコ・タテの問数を確認します。小は最大30マス、大は最大40マスの辺長です。生成中はボタンを待機状態にし、400msを超えると追加の待機表示を出します。開発機Node.jsで800回すべて成功、組別平均は約3〜20msでした。Worker起動やスマホの処理時間は含みません。

GameSessionの時刻取得関数は注入可能です。completedは終了を表し、クリアはfinishReason === 'solved'、途中終了は'revealed'で判定します。再読み込み時に盤面は復元しません。言語設定・最近のヒントID・未送信統計は端末内に保存します。

## ヒントの追加

characters.jsonが標準の3言語名と別名、clues.jsonがキャラクターIDに紐づく題材別ヒントと出典を管理します。2026-10-16確認時点で入門・発展は各173名。公式の主要145名、ウマ娘と確認できる補助17名、既存の漫画オリジナル11名を含みます。全体915件の3言語ヒント、通常問題は各797件です。通常と物語のヒントには選択肢を持たせ、二つ名は原典の実在する称号を維持します。ゲームとタオルの二つ名が両方あれば両方表示します。入門と発展はキャラクターを共有できますが、ヒントの適用区分と抽選重みは別です。

追加時は安定したcharacterIdとヒントid、zh-CN・en・ja、categories、dimension、sourcesを揃えます。roster.jsonの確認済み名簿も保守します。新しい事実にはfactKeyとverifiedAt、近況にはasOfと本文の日付を付けます。「努力家」「走るのが得意」だけの曖昧なヒントは禁止です。競走年・明確な関係・固有の称号・具体的な場面等で特定できる内容にし、楽曲は収録先と独唱表記を確認、多人数企画は人物を区別する情報も添えます。事実と一意性は人による確認が必要です。英字は空白・記号を除き大文字化し、カタカナは小書き文字と長音を各1マスとします。シンデレラグレイのオリジナルキャラクターを原型馬名に置き換えないでください。

旧8盤面は資料・回帰テスト用として残し、通常プレイでは読み込みません。データ変更後はcheck:data、build:worker、test、buildを実行し、worker/pool.generated.jsと変更があるworker/levels.generated.jsをコミットします。生成物の手編集、dist/、認証情報、本機DBのコミットは避けます。

## 統計と更新

analytics.jsが上報・再送・キャッシュを担当します。新APIは/api/v2/で、Pages FunctionのSTATSバインディングからWorkerへ転送し、DBバインディングでD1を使用します。開始時に盤面を検証して解答のハッシュのみ保存し、クリア時に文字を照合します。DBにIP・検索語・解答明細は保存しません。ランダムrunIdで重複排除し、未送信盤面を含むデータは端末に一時保存する場合があります。統計の障害はゲームを止めず、ローカルでは既定で本番DBへ送信しません。

v0.7.1の名簿拡張には新しいD1移行は不要ですが、拡張候補を受理するWorkerを先に公開し、その後フロントエンドを公開します。

v0.7は0002_random_stats.sqlを適用し、Worker、フロントエンドの順で公開します。旧テーブルと旧APIは保持し、旧固定問題の統計を新ランダム問題と混ぜません。フロントだけの公開では更新は完了しません。
